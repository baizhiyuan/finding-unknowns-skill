The "Tuesday shows Sunday" bug wasn't in `report.sql`, so I left that file alone. I fixed the date calculation in `dates.py`. I haven't run the tests or simulated the 00:30 cron run; I only checked that `yesterday()` imports and returns a plausible date.

**Cause:** `deploy/Dockerfile` sets `TZ=UTC`, but the cron job runs at 00:30 Asia/Shanghai, which is 16:30 UTC the day before. On Tuesday at 00:30 Shanghai time, `date.today()` inside the container returns Monday. `yesterday()` then returns Sunday, so the email shows Sunday's sales. The query `report.sql` is correct: it takes a half-open range `[start, end)` over `sold_at_local`.

**Fix:** `yesterday()` in `dates.py` now takes today's date in `Asia/Shanghai` explicitly, so it no longer depends on the container's `TZ`. `weekly.py` calls the same function and had the same bug on Monday 00:45, so it's fixed too.

**Checks:**
- `yesterday()` returned 2026-11-10 when UTC was 2026-11-11 02:18, which is what I expected. Shanghai was already 2026-11-11 10:18 then, so yesterday is the 10th.
- I couldn't run `tests/test_sql.py` because pytest isn't installed here. It only checks the SQL text, so this change doesn't affect it.

**Before you deploy:** `zoneinfo` needs timezone data in the image. `python:3.11-slim` normally includes `/usr/share/zoneinfo`, but I couldn't check that here. If it's missing, add `tzdata` to the image.
