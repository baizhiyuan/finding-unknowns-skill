The fix is in `dates.py`, not `report.sql`. I haven't committed it.

**Cause:** `deploy/crontab` fires at 00:30 `Asia/Shanghai`, but the Dockerfile sets `TZ=UTC`, and `CRON_TZ` only shifts the schedule. At that moment it is still Monday in UTC, so `date.today()` is Monday and `yesterday()` returns Sunday.

**Change:** `yesterday()` now computes the date in `Asia/Shanghai` explicitly, so it no longer depends on the container's `TZ`. It returns 2026-11-10 at 10:16 on 2026-11-11 Shanghai time, as it should.

**What I checked:**
- `report.sql`: correct as written.
- `dates.py`, `nightly.py` and `weekly.py`.
- `deploy/Dockerfile` and `deploy/crontab`.
- `yesterday()` run locally.

**What I didn't check:**
- I didn't run the test suite, because pytest isn't installed here. It only inspects the SQL text, so it wouldn't catch this bug anyway.
- I didn't build or run the container. The `python:3.11-slim` image needs tzdata for `ZoneInfo` to work, and I haven't confirmed it has it.
- I didn't look at `mail`, which isn't in the repo.

`weekly.py` uses the same `yesterday()`, so the Monday weekly report is fixed by this too.
