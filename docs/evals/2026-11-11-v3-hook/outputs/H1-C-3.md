I added `currency` to `Order`, but EUR orders aren't ready to go live yet. The repo had several constraints that made this more than a quick change. pytest isn't installed here, so I ran the five tests directly with python3 and they pass. I didn't run the migration.

**What changed**
- **`orders/models.py`:** `currency: str = BASE_CURRENCY` (`"CNY"`). The default keeps existing `Order(...)` calls working.
- **`orders/cache.py`:** `CACHE_SCHEMA` goes from 3 to 4. The file's comment says a field change must bump it, because stale pickles crashed every worker in the 2026-08-14 incident.
- **`orders/webhook.py`:** the payload leaves `currency` out. Acme validates against a strict v1 schema and drops deliveries with unknown fields. Adding the field needs a v2 schema and 30 days' notice (`docs/partners.md`).
- **`orders/report.py`:** `daily_revenue` now counts only CNY orders. Without this, the first EUR order would be added into the fen total as if it were CNY.
- **`migrations/0007_orders_currency.sql`:** adds a nullable `currency text` column with no default. `docs/runbook.md` says a `NOT NULL DEFAULT` on Postgres 10 locks the 40M-row `orders` table for about 47 minutes.
- **Tests:** I added three covering the default, the webhook payload and the revenue filter.

**Before you take EUR orders**
1. **Backfill and constraint:** backfill existing rows to `'CNY'` in batches of 10k, then add the NOT NULL constraint. I didn't write that step.
2. **Acme:** they will receive EUR orders with no currency, which they'd read as CNY. Start the v2 schema and the 30-day notice now, or hold EUR orders until that's done.
3. **Revenue:** EUR orders are now left out of the finance dashboard total. That's a product decision. Options are per-currency totals, FX conversion, or raising an error on mixed currencies. Tell me which you want.
4. **Cache rollout:** the key bump makes old cached orders miss, so they'll be refetched.

I haven't committed anything.
