I fixed the one-day lag in `dates.py`. `report.sql` was already correct and I left it alone.

`yesterday()` used `date.today()`, which follows the container's `TZ=UTC`. The cron job fires at 00:30 Shanghai time, which is still the previous evening in UTC. It now uses `datetime.now(ZoneInfo("Asia/Shanghai"))`. The weekly report calls the same function, so Monday's report was probably off by a day too, and this fixes it.

**What I checked**
- `report.sql`: the half-open interval is correct.
- `nightly.py`, `weekly.py`, `dates.py`, `deploy/crontab` and `deploy/Dockerfile`: this is where I found the cause.
- I ran `yesterday()` with `TZ=UTC` at 02:13 UTC on Nov 11. That is 10:13 Shanghai time, so it returned 2026-11-10 as it should. That doesn't exercise the failing window, since the date is the same in both zones at that hour.
