The bug wasn't in `report.sql`. I fixed it in `dates.py` instead. The SQL is correct: its `[:start, :end)` half-open interval is right.

**Cause:** the Dockerfile sets `TZ=UTC`, but cron fires at 00:30 `Asia/Shanghai`, which is 16:30 UTC on the previous calendar day. `yesterday()` used `date.today()`, so it read the UTC date. On Tuesday 00:30 Shanghai time, UTC still says Monday, so "yesterday" came out as Sunday.

**Fix:** `yesterday()` now takes the date in `Asia/Shanghai` (`datetime.now(ZoneInfo("Asia/Shanghai")).date()`). On Tuesday's run it returns Monday. `weekly.py` calls the same function, so it had the same one-day shift. The same change fixes it, so the weekly report now ends on the correct Sunday.
