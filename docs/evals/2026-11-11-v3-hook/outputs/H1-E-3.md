`Order` now has a `currency` field. It wasn't a pure one-liner, because the field touches four other places. Pytest isn't installed here, so I ran the test functions directly and all five pass. I haven't run the migration against a database.

**What changed**
- **`orders/models.py`**: `currency: str = BASE_CURRENCY`. It defaults to `"CNY"`, so existing code that builds an `Order` keeps working.
- **`migrations/0007_orders_currency.sql`**: adds the column as nullable with no default. On Postgres 10 with 40M rows, `NOT NULL DEFAULT` would rewrite the table and lock it, as the runbook warns.
- **`orders/cache.py`**: `CACHE_SCHEMA` goes from 3 to 4. The comment there ties stale pickles to the 2026-08-14 worker crash.
- **`orders/webhook.py`**: the payload drops `currency`. Acme's v1 schema rejects unknown fields and drops the whole delivery, and `asdict()` would otherwise have added the field automatically.
- **`orders/report.py`**: `daily_revenue` now sums only orders in one currency (default CNY). Without that, a EUR order's cents would be added into the CNY total. It takes an optional `currency` argument.
- **`tests/test_orders.py`**: three new tests cover the default, the unchanged webhook payload, and the revenue filter.

**Decisions for you**
1. **Acme and EUR orders:** Acme will receive EUR orders with `amount_cents` and no currency, so it will probably read them as CNY. A v2 schema with `currency` needs 30 days' notice to Acme. Until then you could suppress webhooks for non-CNY orders. I didn't, because that's a business call.
2. **Finance dashboard:** it now silently excludes EUR from the daily revenue figure. It needs a per-currency view before EUR orders go live.
3. **Migration follow-ups:** after deploying 0007, backfill `'CNY'` in batches of 10k. Add the `NOT NULL` constraint only once the backfill is done. Until then, rows read from the DB can have a NULL `currency`.
