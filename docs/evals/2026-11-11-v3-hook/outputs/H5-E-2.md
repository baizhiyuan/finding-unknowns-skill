The bug wasn't in `report.sql`. I fixed it in `dates.py`, but I haven't tested it in the container. I ran `nightly.params()` and `weekly.params()` locally, and both returned the expected dates. I didn't run the pytest suite because pytest isn't installed here.

**Cause:** `deploy/Dockerfile` sets `TZ=UTC`, while cron runs at 00:30 `Asia/Shanghai`. `CRON_TZ` only changes when the job fires. The Python process still sees UTC, and 00:30 Tuesday in Shanghai is 16:30 Monday in UTC. So `date.today()` returned Monday and `yesterday()` returned Sunday. The SQL just queried whatever dates it was given.

**Fix:** `dates.py` now takes the date in `Asia/Shanghai` explicitly, via a new `today()` helper that `yesterday()` uses. The result no longer depends on the container's `TZ`. This also fixes `weekly.py`, which uses `yesterday()` and had the same one-day offset.

**Check before deploying:** `zoneinfo` needs timezone data on the system. I believe `python:3.11-slim` ships `tzdata`, but I didn't check. Run `docker run --rm <image> python -c "import dates; print(dates.today())"` after building. If it fails, add `tzdata` to the image.
