I fixed the timezone bug in `dates.py`. `report.sql` is unchanged.

**Cause:** the container sets `TZ=UTC`, while cron fires at 00:30 Asia/Shanghai, which is still the previous day in UTC. On Tuesday 00:30 Shanghai, `date.today()` returned Monday, so `yesterday()` returned Sunday.

**Fix:** `yesterday()` now takes the date in `Asia/Shanghai` explicitly, so it no longer depends on the container's timezone. `weekly.py` uses the same function, so the weekly report had the same one-day shift and is fixed too.

**Checks:**
- I simulated Tuesday 2026-11-10 00:30 Shanghai with the container in UTC. `yesterday()` now returns Monday 2026-11-09. Before the change it returned Sunday.
- I couldn't run the test suite because `pytest` isn't installed here. The only test reads `report.sql` as text, so this change doesn't touch it.

**Before you deploy:**
- `zoneinfo` needs timezone data in the image. I believe `python:3.11-slim` ships it, but I couldn't check the image. If it's missing, add `tzdata` to the Dockerfile.
- I left `ENV TZ=UTC` as it is, in case anything else relies on it.
