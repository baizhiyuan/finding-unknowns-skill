`Order` now has a `currency` field, but EUR orders aren't safe to take yet. The finance report still adds all amounts together whatever the currency. pytest isn't installed, so I called the four test functions directly. They pass.

**What I checked**
- `models.py`, `cache.py`, `webhook.py`, `report.py`, `settings.py`, the webhook schema, the migration, the tests and all three docs.

**What I changed**
- `orders/models.py`: added `currency: str = "CNY"`. The default keeps existing constructors working.
- `orders/cache.py`: bumped `CACHE_SCHEMA` from 3 to 4. The comment there says stale pickles with a different field set crashed every worker in the 2026-08-14 incident.
- `orders/webhook.py`: the payload leaves `currency` out. Acme's v1 schema rejects unknown fields and drops the delivery, and `asdict` would otherwise have added it.
- `migrations/0007_orders_currency.sql`: adds a nullable `currency` column with no default. The runbook says a NOT NULL default on Postgres 10 locks the 40M-row table for about 47 minutes.
- `tests/test_orders.py`: two new tests, one for the default and one that the payload omits `currency`.

**What I didn't check**
- I didn't run the migration against a database or confirm the migration numbering with anyone.
- I haven't looked at the code that creates orders or writes them to the database. It isn't in this repo, so it still needs to set `currency` and handle the NULL values.
