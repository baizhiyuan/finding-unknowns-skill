`Order` now has a `currency` field that defaults to `"CNY"`, so existing callers don't change. pytest isn't installed here, so I ran the five tests by hand and they pass. I haven't run the migration.

Four existing constraints would have broken with a plain new field, so I handled each:

- **Webhook:** `currency` is left out of the `order.created` payload. Acme's v1 schema rejects unknown fields and drops the delivery. Partners won't see the currency until there's a v2 schema, which needs 30 days' notice to Acme (`docs/partners.md`).
- **Cache:** I bumped `CACHE_SCHEMA` from 3 to 4 in `orders/cache.py`, as its comment requires. Old pickles are ignored instead of crashing workers.
- **Database:** `migrations/0007_orders_currency.sql` adds `currency char(3)` as nullable with no default. On Postgres 10 a NOT NULL default on the 40M-row table would lock it for a long time (`docs/runbook.md`).
- **Report:** `daily_revenue` now counts only CNY orders, so EUR amounts aren't added to fen. I added `daily_revenue_by_currency` for per-currency totals.
