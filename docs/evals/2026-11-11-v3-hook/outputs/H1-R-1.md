`Order` now has a `currency` field, default `"CNY"`. Existing constructor calls still work. `pytest` isn't installed here, so I ran the four tests by calling them directly. All four pass. Nothing is committed, and the migration hasn't been run.

**What I checked before acting**
- Every file in the repo, including the runbook, the partner doc, the webhook schema, and the comments in the cache and settings files.

**What changed, and why**
- **Webhook:** `asdict(order)` would have put `currency` into the `order.created` payload. Acme's v1 schema rejects unknown fields and drops the delivery. I strip `currency` from the payload for now. Sending it needs a v2 schema and 30 days' notice to Acme.
- **Migration:** `migrations/0007_orders_currency.sql` adds a nullable column with no default. A NOT NULL default would lock the 40M-row table on Postgres 10, which is what caused the 47-minute outage. The app treats NULL as CNY.
- **Cache:** I bumped `CACHE_SCHEMA` from 3 to 4. Stale pickled Orders crashed the workers in the 2026-08-14 incident.
- **Revenue report:** `daily_revenue` would have added EUR cents to CNY fen. It now sums only CNY orders. I added `daily_revenue_by_currency` for a per-currency breakdown.
- **Tests:** I added tests for the payload and the revenue change.

**What I did not check**
- Whether anything outside this repo uses these models or the pickled cache.
- The real database schema. I only know the `orders` table from the migration and runbook.
- How orders are written to the database. No code in this repo does it.
- Whether Acme is the only webhook consumer.
