The report is no longer a day behind, but the bug wasn't in `report.sql`. I left that file alone because its query is correct. I haven't run the tests (pytest isn't installed here). I did check that `yesterday()` returns 2026-11-10 today.

**Cause:** the cron schedule is `CRON_TZ=Asia/Shanghai`, but the Dockerfile sets `ENV TZ=UTC`. At 00:30 Shanghai time it's still 16:30 the previous day in UTC. `date.today()` in `dates.py` therefore returned the previous day's date, and `yesterday()` went back one more. On Tuesday 00:30 CST that gave Sunday instead of Monday.

**Fix:** `dates.py` now computes the date in `Asia/Shanghai` with `datetime.now(ZoneInfo("Asia/Shanghai"))`, so it no longer depends on the container's timezone.

- **Weekly report:** `weekly.py` also uses `yesterday()`, so the Monday 00:45 report was off by a day too and is fixed by the same change.
- **Timezone data:** `zoneinfo` needs timezone data in the image. `python:3.11-slim` should include it, but check after rebuilding.
- **Alternative:** changing the Dockerfile to `ENV TZ=Asia/Shanghai` would also work. I chose the code change so it doesn't depend on the environment.
