I fixed it in `dates.py`, not `report.sql`. The SQL's half-open `[:start, :end)` interval is correct.

**Cause:** `deploy/crontab` fires at 00:30 `Asia/Shanghai`, but `deploy/Dockerfile` sets `TZ=UTC`. `dates.yesterday()` used `date.today()`, which reads the container clock. On Tuesday at 00:30 in Shanghai it's still Monday 16:30 in UTC. So "yesterday" came out as Sunday, and the email showed Sunday's sales.

**Fix:** `yesterday()` now takes the date in `Asia/Shanghai` instead of the container's timezone. The weekly report uses the same function, so it had the same one-day shift and is fixed too.

**Checks:**
- With `TZ=UTC`, `nightly.params()` returns `{'start': '2026-11-10', 'end': '2026-11-11'}`. The Shanghai date is 2026-11-11, so that's the correct previous day.
- I couldn't run `tests/test_sql.py` because pytest isn't installed here. It only checks the SQL text, which I didn't change.
