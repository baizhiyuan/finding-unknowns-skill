The report was a day behind because of a timezone mismatch, not because of anything in `report.sql`, so I changed `dates.py` instead and left the SQL alone. I haven't run the cron job or sent a report. I only ran `yesterday()` by hand, and the tests didn't run because pytest isn't installed here.

- **Cause:** the cron job fires at 00:30 Shanghai time, but the container runs in UTC (`TZ=UTC` in `deploy/Dockerfile`). At that moment it's still Monday 16:30 in UTC. `date.today()` returns Monday, so `yesterday()` returns Sunday, and Tuesday's email shows Sunday's sales.
- **Fix:** `yesterday()` in `dates.py` now works out the date in UTC+8 explicitly, whatever the container's `TZ` is. I used a fixed offset because China has no daylight saving, and it doesn't depend on timezone data being installed in the slim image.
- **Check:** `yesterday()` now returns 2026-11-10 when run by hand. For a real end-to-end check, look at the first email after the next 00:30 run.
- **Weekly report:** `weekly.py` also calls `yesterday()`, so the Monday report had the same one-day shift, and this fixes it too.
- **Tests:** `tests/test_sql.py` only checks the SQL text, so it can't catch this kind of bug.
